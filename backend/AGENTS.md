# Backend Agent Instructions — FastAPI Modular Monolith

Read the root `AGENTS.md` first. This file adds backend-specific rules.
Binding requirements live in `docs/requirements-prompt.txt` (Persian).

## Stack

Python 3.12 · FastAPI · SQLAlchemy 2.0 (sync sessions) · Alembic ·
Pydantic v2 · Redis + Celery · PostgreSQL. Dev on Windows with venv
(no Docker). Redis runs under WSL2; PostgreSQL 18 runs as a Windows service.

## Layering (strict)

```
router (endpoint) -> service (business logic, transactions)
                   -> repository (queries + mandatory scope filter)
                   -> database
```

- **Router**: validate input shape (Pydantic), call the service, return the
  standard envelope. No business logic, no direct repository access.
- **Service**: all business rules, transaction boundaries, audit writes,
  domain-event emission. Calls repositories and other modules' contracts.
  Raises domain errors from the standard error-code set.
- **Repository**: queries only. Every method takes a scope context and
  applies the scope filter — a query without a scope filter is a bug.
  No business logic. Never imports another module's repository or models.
- Cross-module access goes through `contracts.py` interfaces only.

## Module layout

```
backend/app/
├── core/        config (pydantic-settings), security, errors, logging,
│                tracing, database
├── common/      mixins, pagination, schemas, scope, audit helpers
├── modules/
│   └── <module>/          # user | warehouse | loan | notification | audit | settings
│       ├── models.py      # SQLAlchemy models
│       ├── schemas.py     # Pydantic DTOs
│       ├── repository.py  # scope-filtered queries
│       ├── service.py     # business logic
│       ├── router.py      # /api/v1 endpoints
│       ├── contracts.py   # public interface for other modules
│       └── tests/
├── workers/     celery_app, tasks
└── seeds/       seed_dev.py, seed_prod.py (idempotent; admin password from env)
```

## Models

- Use mixins from `common/mixins.py`: ID (UUID), Timestamp, SoftDelete,
  CreatedBy, UpdatedBy, Version, OrgScope.
- Active-row uniqueness uses partial unique indexes, e.g.
  `CREATE UNIQUE INDEX uq_employee_national_id_active
   ON employees(national_id) WHERE deleted_at IS NULL;`
- Never physically delete rows. Never allow negative inventory
  (constraint + `SELECT ... FOR UPDATE` in services).

## API contract

- Base path `/api/v1`. All list endpoints paginated (`?page=&page_size=`),
  response `{items, page, page_size, total}`; support filter/sort/search
  where the spec requires.
- Errors: `{code, message, details, trace_id}` with codes from the standard
  set (VALIDATION_ERROR, AUTHENTICATION_REQUIRED, AUTHORIZATION_DENIED,
  RESOURCE_NOT_FOUND, DUPLICATE_RESOURCE, CONFLICT_CONCURRENT_UPDATE,
  INSUFFICIENT_STOCK, BUSINESS_RULE_VIOLATION, RATE_LIMITED, INTERNAL_ERROR,
  STALE_VERSION, RESOURCE_LOCKED).
- Keep FastAPI OpenAPI response models accurate — they are the API docs.

## Environment

- All config via pydantic-settings from `.env` (copy `.env.example` first).
- `DATABASE_URL`, `REDIS_URL`, JWT settings, cookie settings, seed admin
  credentials — env only. Never hardcode hosts or secrets.
- JWT: short access token (default 15 min) + rotating refresh token
  (default 7 days) in HttpOnly cookies; CSRF protection on cookie-authed
  mutations.

## Migrations

```
alembic revision --autogenerate -m "<message>"
alembic upgrade head
alembic downgrade -1
```

Always review autogenerated migrations before committing — verify partial
indexes, constraints, and UUID types survived autogeneration.

## Testing

```
pytest                        # all
pytest app/modules/user       # one module
pytest -k loan_validation     # by keyword
```

- Unit: services, validators, scope resolution, loan validation cascade,
  low-stock logic.
- Integration: repositories, scope filters, transaction boundaries,
  database constraints, partial unique indexes, endpoints, outbox.
- E2E: employee+user creation, role/scope assignment, stock movement,
  item request -> fulfillment, low-stock alert + notification, loan
  validation, live SSE notification.

## Windows dev notes

- Redis (WSL2): verify with `wsl redis-cli ping` — expected PONG.
